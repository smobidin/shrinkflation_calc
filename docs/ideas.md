# Отложенные идеи

## Сканирование ценника (OCR → карточка товара)

Сценарий: сфотографировать ценник в магазине, распознать текст, заполнить карточку товара в приложении.

Оценка: прототип — задача средней сложности; надёжный разбор разных форматов ценников — отдельная большая работа.

Важные выводы:
- OCR-модель ML Kit Text Recognition v2 не гарантирована на всех телефонах: unbundled-вариант скачивается через Google Play Services, bundled — включается в APK и работает офлайн, но увеличивает его размер.
- ML Kit v2 не заявляет поддержку русского/кириллицы в списке оцениваемых языков. Для RU-ценников рассмотреть Tesseract (`tesseract4android`) с данными `rus+eng` в assets.
- Обязателен экран ручного подтверждения распознанных полей; никогда не сохранять в БД сразу после OCR.
- Числа парсить как `BigDecimal` с запятой в качестве разделителя (в проекте цены хранятся строками).

## Поиск товара по штрихкоду онлайн

Сценарий: отсканировать штрихкод → найти товар в онлайн-каталоге (название, бренд, характеристики) → пользователь вручную вводит цену.

Возможные источники:
- Open Food Facts — открытая база, бесплатный API по штрихкоду, без ключа для чтения; данные под ODbL, нужна атрибуция; для новых интеграций документация рекомендует v3. Покрытие RU-ассортимента требует проверки.
- Платные RU-агрегаторы (uniPIM, EAN-DB, FoodBase) — ключ API нельзя встраивать в мобильное приложение, нужен сервер-прокси, что конфликтует с offline-first моделью проекта.

Вывод: каталог даёт только название/бренд/характеристики, не цену в магазине. Для пилота — Open Food Facts и явный выключатель онлайн-поиска; результаты кэшировать локально.
